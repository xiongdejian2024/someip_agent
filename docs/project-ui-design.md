# 工程保存与加载界面设计

## 2026-10-04：加载工程的生命周期与取消保护

加载不仅检查页面可见的 active／running，也与服务、仿真、监听的初始化及资源释放共享
门禁。旧实现的三个控制回归实际复现了初始化窗口、状态停止但资源未释放、选择线程未结束
仍可切换地址的问题；现已拒绝这些冲突，HTTP 返回 409，不会代用户停止任务。

SQLite 在同一事务读取并选择工程，返回选择时的完整视图；缺失或损坏工程不替换当前选择。
请求取消无法停止数据库线程，加载会等待其明确结束再释放模型锁和配置预约；多次取消仍
受保护。若选择已完成，内存模型与数据库选择同步，但调用方仍收到取消，不能冒称成功回执。
这一行为不修改网卡、不自动运行。未知结果仍需工程页面的修订核对和明确加载流程。

## 调研与取舍（2026-10-03 至 2026-10-04）

参考 [VS Code 工作区官方说明](https://code.visualstudio.com/docs/editing/workspaces/workspaces)：
工程需要承载配置与编辑布局，而不只是一个文件名。本项目将模型、服务、激励与工作区配置
作为工程草案；保存、选择重启恢复目标和运行任务仍是不同动作，不照搬 IDE 的自动执行行为。

参考 [Nielsen Norman Group 的渐进式呈现](https://www.nngroup.com/articles/progressive-disclosure/)：
常用动作先呈现，低频或高级动作分层展开。以下布局和安全保护是本项目的设计判断，
不把资料当作 SOME/IP 运行约束或其他产品完整功能的证明。

现有问题：所有操作堆在一个折叠菜单；缺少未保存提示；首次保存后是否切换不明确；
列表缺少搜索和内容预览；恢复备份与加载工作区混在一起；侧栏显示固定假工作区名。

## 新布局

- 常驻工程栏：已打开工程、修订、草案状态、保存配置、加载工程、工程管理。
- 加载区：名称搜索、带时间与短 ID 的工程列表、配置数量及模型预览、明确打开。
  同名工程仍是不同 ID；搜索排除当前选项时清除选择，不从隐藏选项启动加载。
- 管理区分为名称与另存、历史备份、导入／导出、高级配置；一次显示一个区域。
- 首次保存、另存和导入只创建工程，提示等待明确加载；不覆盖当前工程或自动切换。
- 恢复备份生成新修订，保留当前草案和原历史；加载前禁用基于旧 revision 的保存。
  明确加载后才更新工作区和模型，不自动发包或代用户停止活动任务。
- 导出已保存工程和导出当前草案分别命名；后者包含未保存配置，但不持久化工程。

## 数据与操作保护

草案和当前已保存修订分别保留。加载、放弃 JSON 修改及恢复备份使用显式确认；
确认期间草案再次变更时禁用继续。未保存草案或未校验 JSON 修改触发离页提示。
JSON 编辑还未校验载入时，禁用保存，避免误把编辑器外的旧配置保存成成功。

保存请求冻结当时的不可变草案；返回时若已有新编辑，不用旧响应覆盖新草案。
首次载入和 ARXML 导入同步模型投影；保存完整草案，包括明确校验过的模型编辑。
模型编辑仅在明确加载工程后激活，不在保存或 JSON 校验时替换运行模型。

继续复用 lossless-json、React、SQLite、现有校验和 revision 冲突检查，不加依赖。
共享的大模型引用未改变时，输入名称或说明不重复序列化整个 ARXML。
工程大响应使用有界 30 秒请求超时。写请求断线／超时意味着结果未知，不自动重试；
禁用重复写入，提示刷新列表、核对修订并明确加载，不能把未知结果显示成确定失败。
列表或预览读取失败分别提示，不将已经成功保存的工程误报为保存失败。

实测 131 服务模型草案约 4.3 MB，格式化后约 7.6 M 字符；放入 textarea 后出现浏览器
操作超时。内联 JSON 编辑限制为 1 MiB UTF-8，超限不截断，提供完整草案导出和文件导入。
工程格式／文件的 8 MiB 后端上限不变；不是把内联编辑限制冒称成文件或协议限制。
