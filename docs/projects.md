# 工程配置管理

任意页面顶部工程栏可直接保存或展开“加载工程”。“工程管理 → 名称与另存”编辑名称和说明。
加载区先搜索、选择和预览，再明确打开；历史、导入／导出和高级配置按区域呈现。
第一次保存或另存会创建一个独立工程；
从列表明确打开后才设为下次重启恢复目标。保存不是启动，打开也不是启动。
切换前必须停止并释放服务会话、仿真和监听；故障但未释放的服务也阻止切换。

工程包含当前模型投影、服务成员配置、完整事件周期参数、公共时钟同步草案、标量仿真工作集、监听草案和波形选择。
服务页“加入工程草案”无需启动服务；已保存的多成员配置可以用“明确启动此配置”手动初始化。
仿真页的工作集和激励参数、监控页监听配置与示波器勾选会进入草案，仍需点击保存才能持久化。
完整配置可在“查看/编辑配置草案”中编辑，通过后端校验后载入；校验本身不保存或启动。
内联 JSON 编辑限 1 MiB UTF-8，大工程用“导出当前草案 JSON”外部编辑后再导入新工程，
不截断内容；工程文件上限仍为 8 MiB。编辑器未校验载入的修改不会由普通保存按钮保存。
模型编辑也保留在草案中，明确加载工程时才激活。加载前提示未保存更改，返回可保留草案。
保存期间产生的新编辑不会被旧保存响应覆盖。写入超时／断线显示结果未知，请核对修订并
明确加载，不自动重复写入。详情和交互设计依据见 `project-ui-design.md`。
工程中尚不能由页面呈现的配置可在 JSON 草案中查看，不能把尚未交付的动态激励当成已支持。

导出使用已保存的工程，不是未保存的草案。导入 JSON 创建新工程，不覆盖当前工程或恢复运行。
“高级配置 → 导出当前草案 JSON”是独立入口，包含未保存配置，不持久化工程或切换工作区。
格式 v2；v1 在导入时补空周期列表。v1/v2 缺少 `sync_groups` 时补空列表，旧工程无需转换。
`sync_groups` 最多 16 项，每项为 `service_profile` 与原生 `ServiceSyncCommand` 配置；
引用工程 services 的名称，每个服务配置最多一组。保留完整事件模板、源、CSV、状态图、
uint64 种子、准备时暂停选项与倍率，不保存 group_id、逻辑时间、PID 或运行状态。
服务页“多事件公共时钟 → 同步配置草案”可选择工程服务配置、载入同步草案或复制周期草案，
编辑完整事件 JSON 列表后明确“加入工程草案”，再点击顶部保存。载入和编辑不改变运行组。
保存、导入、加载和重启均不会准备或启动同步组；实际运行再由原生完整预编译校验。
未来未知版本、密钥、主机路径或发送授权字段拒绝导入。
发送白名单、原生二进制路径、模型凭据与升级签名密钥属于本机设置，不在工程中。
工程携带模型投影而不是任意文件引用，不会按工程给出的路径读取宿主文件。

保存须提交 `expected_revision`，冲突返回 409，需刷新再保存。每工程保留最近 20 个旧修订；
恢复备份生成新修订，不删除当前内容。恢复后还需明确打开，以重新加载页面/模型配置。
网页恢复后保留当前草案，等待明确加载；此期间禁止拿旧修订再次保存当前工程。
最多 100 个工程，单文档 8 MiB。工程和历史存于应用数据目录的 SQLite 数据库。

API 位于 `/api/v1/projects`，OpenAPI 包含创建、保存、校验、当前、打开、导入、导出和备份恢复。
原生与网页验收记录见 `p0-p2-delivery.md`；工程管理不是自动场景执行器或线上回放器。
