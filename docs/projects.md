# 工程配置管理

任意页面顶部展开“工程”，配置工程名后保存。第一次保存或另存会创建一个独立工程；
从列表明确打开后才设为下次重启恢复目标。保存不是启动，打开也不是启动。
切换前必须停止并释放服务会话、仿真和监听；故障但未释放的服务也阻止切换。

工程包含当前模型投影、服务成员配置、完整事件周期参数、标量仿真工作集、监听草案和波形选择。
服务页“加入工程草案”无需启动服务；已保存的多成员配置可以用“明确启动此配置”手动初始化。
仿真页的工作集和激励参数、监控页监听配置与示波器勾选会进入草案，仍需点击保存才能持久化。
完整配置可在“查看/编辑配置草案”中编辑，通过后端校验后载入；校验本身不保存或启动。
工程中尚不能由页面呈现的配置可在 JSON 草案中查看，不能把尚未交付的动态激励当成已支持。

导出使用已保存的工程，不是未保存的草案。导入 JSON 创建新工程，不覆盖当前工程或恢复运行。
格式 v2；v1 在导入时补空周期列表。未来未知版本、密钥、主机路径或发送授权字段拒绝导入。
发送白名单、原生二进制路径、模型凭据与升级签名密钥属于本机设置，不在工程中。
工程携带模型投影而不是任意文件引用，不会按工程给出的路径读取宿主文件。

保存须提交 `expected_revision`，冲突返回 409，需刷新再保存。每工程保留最近 20 个旧修订；
恢复备份生成新修订，不删除当前内容。恢复后还需明确打开，以重新加载页面/模型配置。
最多 100 个工程，单文档 8 MiB。工程和历史存于应用数据目录的 SQLite 数据库。

API 位于 `/api/v1/projects`，OpenAPI 包含创建、保存、校验、当前、打开、导入、导出和备份恢复。
原生与网页验收记录见 `p0-p2-delivery.md`；工程管理不是自动场景执行器或线上回放器。
